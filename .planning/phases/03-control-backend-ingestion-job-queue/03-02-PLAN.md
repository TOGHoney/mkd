<objective>
Implement the asynchronous knowledge ingestion pipeline using BullMQ and Redis. When a company adds a documentation URL, the backend enqueues a background job, immediately returns HTTP 202 with `job_id`, dispatches crawling to the FastAPI engine, and broadcasts real-time progress via Server-Sent Events (SSE).

Purpose: Prevents long-running web crawling from blocking HTTP request threads or causing gateway timeouts, providing responsive UX and transparent progress tracking.
Output: BullMQ queue, background worker, source controller, job progress SSE endpoint, and automated test suite.
</objective>

<threat_model>
- T-03-03: Job queue starvation, infinite crawl loops, and SSRF attacks via malicious crawl URLs (ASVS 12.6). Mitigation: Source URLs validated for protocol (`http`/`https`); localhost and private IP addresses blocked unless explicitly permitted in development; max crawl depth and page limits strictly enforced.
</threat_model>

  <name>Task 1: IngestionJob Model & BullMQ Queue / Worker Architecture</name>
  <files>backend-node/src/models/IngestionJob.js, backend-node/src/queues/ingestionQueue.js, backend-node/src/queues/ingestionWorker.js</files>
  <read_first>backend-node/src/models/Source.js, backend-node/src/config/redis.js</read_first>
  <action>
    1. Create `backend-node/src/models/IngestionJob.js`:
       - Schema:
         - `job_id`: String, required, unique, indexed
         - `workspace_id`: ObjectId ref 'Workspace', required, indexed
         - `source_id`: ObjectId ref 'Source', required, indexed
         - `url`: String, required
         - `status`: String, enum ['queued', 'crawling', 'indexing', 'completed', 'failed'], default 'queued', indexed
         - `progress_percent`: Number, default 0
         - `pages_crawled`: Number, default 0
         - `chunks_indexed`: Number, default 0
         - `error_message`: String, default null
         - `started_at`: Date
         - `completed_at`: Date
         - `createdAt`: Date
    2. Create `backend-node/src/queues/ingestionQueue.js`:
       - Instantiates BullMQ `Queue('ingestion-jobs', { connection: getRedisClient() })`.
       - Implements `addIngestionJob({ workspaceId, sourceId, url, maxPages = 50, maxDepth = 3 })`:
         - Generates UUID `job_id`.
         - Persists initial `IngestionJob` record in MongoDB with status `queued`.
         - Pushes job data to BullMQ queue.
         - Returns created `job_id`.
       - Provides in-memory queue fallback if Redis connection is unavailable in local test environments.
    3. Create `backend-node/src/queues/ingestionWorker.js`:
       - Instantiates BullMQ `Worker('ingestion-jobs', processor, { connection: getRedisClient() })`.
       - `processor(job)`:
         - Updates `IngestionJob` status to `crawling`, `progress_percent: 25`, `started_at: new Date()`.
         - Sends `POST http://localhost:8000/api/v1/ingest/crawl` with:
           `{ workspace_id, url, max_pages, max_depth }`.
         - Updates status to `indexing`, `progress_percent: 75`.
         - When FastAPI returns success (`pages_crawled`, `chunks_created`):
           - Updates `IngestionJob` to `completed`, `progress_percent: 100`, `pages_crawled`, `chunks_indexed`, `completed_at: new Date()`.
           - Updates `Source` status to `indexed`, `pages_count`, `last_crawled_at: new Date()`.
         - Catch error:
           - Updates `IngestionJob` to `failed`, `error_message`.
           - Updates `Source` status to `failed`.
       - Emits progress events on an `EventEmitter` for the SSE streamer.
  </action>
  <verify>node -e "const j = require('./backend-node/src/models/IngestionJob'); const q = require('./backend-node/src/queues/ingestionQueue'); console.log('Job model and queue loaded')"</verify>

    - `ingestionQueue.js` exports `addIngestionJob`
    - `ingestionWorker.js` handles status transitions (queued -> crawling -> indexing -> completed/failed)
  </acceptance_criteria>

         - Endpoint for Server-Sent Events (`GET /api/v1/jobs/:jobId/progress`).
         - Validates job exists.
         - Sets SSE headers:
           ```javascript
           res.setHeader('Content-Type', 'text/event-stream');
           res.setHeader('Cache-Control', 'no-cache');
           res.setHeader('Connection', 'keep-alive');
           res.flushHeaders();
           ```
         - Immediately sends current job state: `res.write(`data: ${JSON.stringify(job)}\n\n`)`.
         - Listens to worker progress events for `job_id` and flushes updates.
         - When job reaches `completed` or `failed`, sends final event and calls `res.end()`.
         - Cleans up listener on `req.on('close')`.
    2. Create `backend-node/src/routes/jobRoutes.js`:
