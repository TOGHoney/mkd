<objective>
Scaffold the Node.js Express control backend (`backend-node`), establish MongoDB schemas (User, Workspace, Source), implement JWT authentication, and guarantee multi-tenant authorization so users can only access their provisioned workspace.

Purpose: Establishes the authoritative control plane for authentication, tenant provisioning, and configuration storage, generating unique widget keys for frontend embedding.
Output: Working Express backend with authentication, workspace management routes, and unit tests.
</objective>

<threat_model>
- T-03-01: Cross-tenant data leakage via forged or mismatched `workspace_id` in API headers or route parameters (ASVS 4.1). Mitigation: `requireWorkspaceAccess` middleware validates that the authenticated user owns the requested `workspace_id` before routing.
- T-03-02: Credential theft and weak password storage (ASVS 2.1). Mitigation: Passwords hashed with bcrypt (salt rounds >= 10); JWT signed with secret key and expiry.
</threat_model>

<task type="auto">
  <name>Task 3: Authentication, Tenant Isolation Middleware & Server Setup</name>
  <files>backend-node/src/middlewares/auth.js, backend-node/src/controllers/authController.js, backend-node/src/controllers/workspaceController.js, backend-node/src/routes/authRoutes.js, backend-node/src/routes/workspaceRoutes.js, backend-node/src/server.js, backend-node/tests/auth.test.js</files>
  <read_first>backend-node/src/models/User.js, backend-node/src/models/Workspace.js</read_first>
  <action>
    1. Create `backend-node/src/middlewares/auth.js`:
       - `requireAuth`: validates Bearer JWT token from `Authorization` header, attaches decoded payload to `req.user`.
       - `requireWorkspaceAccess`: checks `req.params.workspaceId || req.body.workspace_id || req.headers['x-workspace-id']`. Validates that the workspace exists and its `owner_id` matches `req.user.id`. If not matching, returns HTTP 403 Forbidden (`{ error: 'Unauthorized cross-tenant access' }`).
    2. Create `backend-node/src/controllers/authController.js`:
       - `register(req, res)`:
         - Validates email and password (min length 6).
         - Checks existing user.
         - Creates User.
         - Auto-provisions default Workspace: `name: "${user.name}'s Workspace"`, generates `api_key` (`sk_live_${uuid}`) and `widget_key` (`wk_live_${uuid}`).
         - Generates JWT token with `{ id: user._id, email: user.email }`.
         - Returns HTTP 201 with `{ token, user, workspace }`.
       - `login(req, res)`:
         - Validates credentials using `comparePassword`.
         - Retrieves user's default workspace.
         - Returns HTTP 200 with `{ token, user, workspace }`.
       - `getMe(req, res)`: returns current user and workspaces.
    3. Create `backend-node/src/controllers/workspaceController.js`:
       - `getWorkspaces(req, res)`: list user's workspaces.
       - `getWorkspace(req, res)`: get details including `widget_key` and settings.
       - `updateSettings(req, res)`: update `allowed_domains` and `widget_settings`.
       - `rotateKeys(req, res)`: regenerate `widget_key` or `api_key`.
    4. Set up routes in `src/routes/authRoutes.js` and `src/routes/workspaceRoutes.js`.
    5. Create `backend-node/src/server.js`:
       - Mounts middleware: `cors()`, `express.json()`.
       - Mounts `/health` endpoint returning `{ status: 'ok', service: 'supermemory-control-backend' }`.
       - Mounts `/api/v1/auth` and `/api/v1/workspaces`.
       - Exports `app` for testing and calls `app.listen(PORT)` if executed directly.
    6. Write automated unit test in `backend-node/tests/auth.test.js`:
       - Tests user password hashing and verification.
       - Tests token signing and decoding.
       - Tests workspace provisioning with `widget_key` prefix `wk_live_`.
       - Tests tenant isolation check rejecting mismatched owner IDs.
  </action>
