<objective>
Build the Knowledge Sources Management and Real-Time Ingestion Progress Monitor (`DASH-02`) in `frontend-dashboard/`. Enable administrators to add documentation websites or sitemaps, monitor background BullMQ crawl execution live via Server-Sent Events (SSE), observe indexed page counts and vector chunks, and manage knowledge sources.

Purpose: Provide company admins with visual control and real-time observability over how their company knowledge is ingested, vectorized, and maintained.
Output: Sources management view, URL crawl submission modal, real-time SSE progress monitor, and automated test suite.
</objective>

<threat_model>
- T-05-04: Client-side Server-Side Request Forgery (SSRF) inputs (ASVS 12.6). Mitigation: Client-side validation blocks `localhost`, `127.0.0.1`, and private IP ranges before sending requests to backend, which also validates.
- T-05-05: Denial of service through unbounded crawl parameters. Mitigation: Client restricts `max_pages` to a range of 1-200 and `max_depth` to 1-5 with step controls.
</threat_model>

  <action>
    Implement `frontend-dashboard/src/api/sourcesApi.js`:
    1. `fetchSources()`: calls `GET /api/v1/sources` with `x-workspace-id` header.
    2. `createSource({ name, url, type, max_pages, max_depth })`: calls `POST /api/v1/sources`. Validates URL protocol (`http://` or `https://`) and blocks private/restricted hostnames. Returns `{ source, job_id, status }`.
    3. `deleteSource(id)`: calls `DELETE /api/v1/sources/:id`.
    4. `subscribeJobProgress(jobId, { onProgress, onComplete, onError })`:
       - Opens native `EventSource` to `/api/v1/jobs/${jobId}/progress` (or falls back to polling `GET /api/v1/jobs/${jobId}`).
       - Parses SSE messages: `{ status, pages_crawled, total_chunks, current_url }`.
       - When `status === 'completed'` or `status === 'failed'`, triggers `onComplete()` and closes the connection.
       - Returns cleanup function `() => eventSource.close()`.
  </action>
